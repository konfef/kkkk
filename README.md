# Telegram-бот для записи к мастеру маникюра

Стек: **Python 3.10+**, **aiogram 3.x**, **SQLite** (через `aiosqlite`), **APScheduler**.

## Структура проекта

```
nail_bot/
├── bot.py                  # точка входа
├── config.py                # токен, ID админа, ID/ссылка канала
├── requirements.txt
├── database/
│   └── db.py                 # вся работа с SQLite (слоты, дни, записи)
├── states/
│   └── states.py             # FSM-состояния (запись клиента + все админ-сценарии)
├── keyboards/
│   ├── calendar_kb.py         # универсальный inline-календарь
│   ├── user_kb.py             # клавиатуры для клиента
│   └── admin_kb.py            # клавиатуры для админ-панели
├── handlers/
│   ├── common.py              # Прайсы / Портфолио (без FSM) + служебные callback'и
│   ├── user.py                 # запись, отмена записи, проверка подписки
│   └── admin.py                # админ-панель целиком
└── utils/
    ├── subscription.py         # проверка подписки на канал через getChatMember
    └── scheduler.py             # напоминания за 24ч на APScheduler
```

## Установка

```bash
cd nail_bot
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

Откройте `config.py` и укажите (или задайте переменными окружения):

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather) — **обязательно**
- `ADMIN_ID` — ваш Telegram ID (узнать можно у [@userinfobot](https://t.me/userinfobot)) — **обязательно**
- `CHANNEL_ID` / `CHANNEL_LINK` — **опционально**. Канал, подписка на который обязательна для записи
- `SCHEDULE_CHANNEL_ID` — **опционально**. Канал, куда бот публикует расписание при каждой новой записи

**Если у мастера нет канала — просто не заполняйте `CHANNEL_ID`, `CHANNEL_LINK` и `SCHEDULE_CHANNEL_ID`**
(оставьте пустыми / не задавайте переменные окружения). Бот сам определит, что канал не настроен:
проверка подписки перед записью отключится, публикация расписания в канал не будет выполняться,
а всё остальное (запись, отмена, напоминания, админ-панель) продолжит работать как обычно.

Если канал всё же используете — учтите: чтобы `getChatMember` работал, бот должен быть администратором
в `CHANNEL_ID`. Чтобы публикация расписания работала — администратором в `SCHEDULE_CHANNEL_ID`.

Переменные окружения (альтернатива правке config.py):
```bash
export BOT_TOKEN="123456:AA..."
export ADMIN_ID="123456789"
export CHANNEL_ID="-1001234567890"
export CHANNEL_LINK="https://t.me/your_channel"
```

## Запуск

```bash
python bot.py
```

При первом запуске автоматически создаётся файл базы данных `salon.db` со всеми таблицами.

## Как пользоваться

1. Как админ откройте бота → в главном меню появится кнопка **«⚙️ Админ-панель»** (видна только `ADMIN_ID`).
2. Через **«➕ Добавить рабочий день»** задайте день, время начала/окончания работы и длительность слота — бот сам нарежет слоты (например, 09:00–18:00 по 60 минут → 9 слотов).
3. Точечно скорректировать расписание можно через **«➕ Добавить слот»** / **«➖ Удалить слот»**.
4. Клиент в главном меню жмёт **«📅 Записаться»** → бот проверяет подписку на канал → календарь → время → имя → телефон → подтверждение.
5. При подтверждении: запись сохраняется в БД, слот занимается, вам (админу) и в `SCHEDULE_CHANNEL_ID` уходят уведомления, а за 24 часа до визита клиенту автоматически придёт напоминание.
6. Клиент может отменить запись сам («❌ Отменить запись»), либо это может сделать админ («❌ Отменить запись клиента») — слот освобождается, напоминание снимается.

## Что стоит доработать в первую очередь

1. **Часовой пояс.** `APScheduler` в `bot.py` захардкожен на `Europe/Moscow` — поменяйте под реальный пояс мастера, иначе напоминания придут не в то время.
2. **Персистентность задач планировщика.** Сейчас `AsyncIOScheduler` держит задачи в памяти, а при старте бота они пересоздаются из активных записей (`restore_reminders`) — это работает, но если нужен более надёжный вариант, замените `MemoryJobStore` на `SQLAlchemyJobStore`/тот же `salon.db`, чтобы не терять точное время следующего запуска между рестартами.
3. **Одновременные запросы на один слот.** Проверка «слот свободен» и его бронирование сейчас не атомарны (race condition при двух клиентах одновременно). Для прототипа это не критично, но при реальной нагрузке стоит обернуть подтверждение брони в транзакцию с `SELECT ... FOR UPDATE`-подобной блокировкой (SQLite: `BEGIN IMMEDIATE`).
4. **Валидация телефона.** Сейчас это простая проверка на 10+ цифр — можно подключить `phonenumbers` для нормализации и проверки кода страны.
5. **Логирование записей в CSV/Excel** или простая веб-страница со статистикой для мастера — сейчас данные видны только через «Расписание на дату» в самом боте.
